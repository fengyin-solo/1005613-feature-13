# 城市集中供热管网与换热站运行管理平台

面向一次二次管网台账、换热站运行、水力平衡调节、热计量抄表、抢修处置、停暖通知与热费结算的一体化城市集中供热运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `district-heating:entries` 这一项，或调用 `resetModule(模块)`。

## 抢修处置的归属与流转口径

抢修页与其余模块不同，状态流转收口在 `frontend/src/api/repair-service.ts`，口径常量与轮值花名册在
`frontend/src/data/repair.ts`，轮值数据另存在 localStorage 的 `district-heating:repair-roster`：

- **归属管控**：抢修单按「所属片区」当前值班抢修队落归属（`归属抢修队`）。只有该单 `当前值班队`
  的值班人能改故障类型、到场时间（以及补影响面积）；跨队提交一律打回并说明原因，打回也写入单据操作留痕。
- **轮值交接**：四个片区各有甲乙两队轮值，「轮值交接」把当前队向后换一位；未恢复的单子
  `当前值班队/当前值班人` 跟着新班走，`归属抢修队` 不动，历史记录仍归原队；已恢复、已升级的单不移交。
  页面顶部可切换值班身份（抢修队+值班人），用于验证跨队打回。
- **状态机**：`待派修 → 抢修中 → 已恢复`，`抢修中 → 已升级`，越级流转直接挡回。已恢复、已升级整单只读。
- **到场时间一套口径**：抢修详情与抢修台账共用行上的同一个「到场时间」，没有两处数据；按既有抢修口径
  核定时间先后（报修 ≤ 到场 ≤ 恢复），并按派修时刻对应班次算时限——白天 45 分钟，夜间（20:00–次日08:00）
  时限单独算，90 分钟，超时在台账标红。
- **挂起**：影响面积缺失的新单先挂起，补齐前不能派修。
- **重复派修**：同片区、同管段、同故障类型且未恢复的单只落一条，重复登记打回并指向原单。
- **恢复结果**：确认恢复后自动在站点巡检生成一条 `待整改` 记录（带来源抢修单号），巡检页可用
  「只看抢修恢复待整改」筛选。抢修页「复位抢修数据」会同时复位抢修单、巡检来源单与轮值花名册。
